# M2-4 — 원문 보존·원자적 삭제·로그 개인정보 보호

검증일 2026-10-22. 운영 배포/DB 변경/실제 Meta 발송 없음.

- 90일 원문 정리는 모든 상태에 적용하고 발송 원장·리포트 숫자를 유지한다. 기존 unguarded legacy의 3일/180일 정리 관례를 유지하며 guarded/campaign 원장을 cascade 삭제하지 않는다.
- 초기 scoped 6개 파일/29개 테스트 통과(12.86초). 이후 atomic 삭제 실패 rollback, migration empty up/down/up와 redaction 기록 보존, 안전한 오류 로그를 추가해 5개 파일/20개 테스트 통과(13.50초).
- 실제 PDF 메모리 TTL 타이머/32개 상한/삭제 generation을 검사한다. 원문 삭제 전후 report metric/snapshot 동일, unknown 상태/시도 횟수 보존, flag OFF에서도 삭제, 신규 원문 보존, 설정 검증, 공유/referral/inbox/cache의 계정 삭제를 확인했다.
- 삭제 도중 DB trigger로 오류를 강제한 경우 연결 상태/공유 자료가 rollback되고 완료 기록이 생성되지 않았다. 기존 서명 callback/계정 삭제/worker cleanup/PDF 회귀를 포함했다.
- 운영 IGSID/comment/provider ID의 장기 보존은 Q14 제품 정책 항목이며 이번 원문 삭제를 완전한 익명화로 표시하지 않는다. 외부 PDF 파일 저장소는 없으며 다른 프로세스 cache는 60초 안에 만료, 공유 접근은 DB로 차단한다.

타입/lint/build/전체 회귀는 최종 결과를 추가한다. [설계 §21](../01-design.md), [운영 절차](../runbook.md)에 확인 방법과 배포 시 인덱스 잠금 고려 사항을 기록했다.
