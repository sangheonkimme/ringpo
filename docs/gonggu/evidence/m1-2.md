## 250계정·댓글 3,000개

[원본 JSON](m1-2-load.json). 전용 PostgreSQL 17-alpine, 2 vCPU/8GB 공유 호스트, 연결 풀 10개, router 동시성 32로 측정했다. 250개 계정에 각각 예고 공구를 생성하고 **전체 합계 3,000개 댓글**을 넣었다. 각 댓글의 웹훅을 3번 재전달했다.

가상 수신 시각은 10분에 걸쳐 분포하지만 **실제 10분 실시간 유입 시험이 아니다**. 메타데이터 API는 프로세스 안의 지연 없는 fixture이며 네트워크 지연·Meta rate 제한은 이 수치에 포함되지 않는다. 실제 발송의 누락·중복·rolling-hour 상한·완료 ETA는 후속 dispatch 시험에서 측정한다.

입력 이벤트 ID 집합과 private job의 source event ID 집합을 전수 비교했다. private reply claim 3,000개, initial-contact 의도 3,000개, 전체 멱등 키 6,000개의 유일성을 검사했다. 별도 통합 테스트에서 같은 사람의 여러 댓글, lease 만료·늦은 worker, 새 DB 연결을 통한 재시작 후 작업 보존도 확인한다.

## 회귀·불변식

기존 회귀를 포함한 **45개 파일 / 296개 테스트 통과** (127.63초). `pnpm typecheck`, `pnpm lint`, `pnpm build:worker`, `git diff --check`도 통과했다.

- 캠페인 NFC 매칭 표: 분해 한글, `링크요`/`링크!!`/`링크 주세요`, 영문 case, 가족/국기/키캡 emoji, exact, 제외어, 빈 키워드. 기존 NFKC/emoji-only 키워드는 보존한다.
- 캠페인 > 게시물 specific > 계정 all. 제외어는 legacy로 넘기지 않는다. 수신 시점의 키워드·effective 상태와 저장 상태를 구분해 보존한다.
- 서명된 webhook 3회 → 이벤트/잡 하나의 묶음. webhook 경로에서는 Meta 메타데이터/송신 API를 호출하지 않는다.
- 댓글의 Meta 작성 시각으로 7일−1시간 deadline을 계산한다. 작성 시각 누락은 bounded retry, 신원 불일치/미래 시각은 실패, 수신 시각 대체는 금지한다.
- flag OFF는 이미 캠페인 경로에 들어온 댓글을 보류하며 기존 자동화로 돌리지 않는다. OFF 이후 새 legacy 댓글은 기존 경로로 처리한다.
- 토큰 만료는 댓글을 버리지 않고 재인증까지 보관한다. sender/계정 데이터 삭제는 관련 작업·참가자·권리도 삭제한다.
- 시도하지 않은 expired/canceled 잡만 새 댓글로 교체할 수 있다. sent/unknown/시도한 잡의 사람 단위 권리는 유지한다.
- migration 0002/0003의 up/down/up은 각각 독립 DB에서 확인하며, 수신/잡 데이터가 있는 상태의 down은 거부한다.

## 배포 경계

기능 플래그 기본 OFF. 구 worker는 `campaign_*` 이벤트 상태를 claim하지 않는다. additive migration → 호환 worker → 수집 분기를 가진 웹 순으로 배포한다. 이 PR만으로 DM/공개 답글이 실제 전송되지는 않는다. [운영 절차](../runbook.md).
