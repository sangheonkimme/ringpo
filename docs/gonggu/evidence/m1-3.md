# M1-3 발송 엔진 검증

확인일: 2026-10-21 UTC. 대상은 PG 발송 엔진·계정 보호 설정·화면이며, 실행 worker의 실제 캠페인 송신 루프는 M1-4의 추적 링크/팔로우/legacy 공통 예산 연결 이후 활성화한다. 운영 DB 변경과 외부 Meta 호출은 0건이다.

## 자동 테스트

기존 자동화 회귀를 포함해 50개 파일/329개 테스트를 통과했다(245.85초). 이후 5xx 응답의 형식 오류처럼 보이는 코드도 자동 fallback하지 않는 회귀 사례를 추가했으며, 관련 5개 파일/48개 테스트를 다시 통과했다. 추가로 DM 보호 오류가 공개 답글도 멈추고, 이미 진행 중인 공개 답글의 성공이 새 중지를 해제하지 않는 경합 사례를 추가했다. 마지막 관련 2개 파일/30개 테스트와 변경된 rollback 테스트를 통과했다. 현재 테스트 수는 331개다.

- DB에 호출 의도/permit을 먼저 commit하고 Meta 요청 중 transaction을 점유하지 않는다.
- 3~5초 지터는 due 시각으로 저장한다. 여러 worker가 같은 account/channel을 동시에 송신하지 않는다. EDF 정렬, 최신 템플릿, 수동 조기 오픈 후 같은 잡 재예약을 검증한다.
- 호출 전 lease 유실은 재개, 호출 후 worker 유실/timeout/5xx는 unknown, 늦은 성공 응답은 late evidence로 보관한다. 호출 전에 짧은 permit이 만료되면 API를 호출하지 않고 시도 횟수를 돌려놓는다.
- 401건을 단일 계정에서 가상 시계로 발송하여 실제 call-start 원장의 모든 rolling-hour 구간이 400건 이하임을 확인한다. 재시작/유휴 후 burst를 쌓지 않는다.
- 5분 안의 5회 연속 rate 오류, 6시간 자동 pause, half-open 실패 연장/성공 재개, 수동 정지와 정책 오류 확인, cooldown 보존, DB outbox를 검증한다.
- flag OFF, 24시간 창 밖, 기한 만료, 다른 셀러의 설정 변경, 오래된 version을 거부한다. 명확한 Meta 형식 거부만 text fallback 후보가 되고 일반 code 100/5xx/network는 두 번째 private reply를 만들지 않는다.
- 0004 migration up/down/up, 발송 예산이 생긴 후 down 거부를 전용 DB에서 확인한다.

## 250계정 발송 부하

전용 PostgreSQL 17, pool 10, HTTP 동시성 64, 2 vCPU/8GB 공유 호스트. 이 시험은 **직접 만든 영속 발송 잡**부터 시작한다. 웹훅 수집/메타데이터 처리 부하는 [M1-2](m1-2.md)에서 별도로 측정했으며, 두 결과를 단순 합산해 전체 서비스 수용량으로 표현하지 않는다.

### 가상 시계 + 실제 로컬 HTTP

[JSON](m1-3-virtual.json). 250계정에 private reply 3,000건, HTTP 응답 지연 100ms. 발송 간격은 가상 시계로 진행한다. 누락 0, 중복 0, unknown 0. 최적화 전 94.769초에서 반복 조회/round trip을 줄인 후 71.525초로 감소했다. 가상 drain은 102초다. 이는 실제 Meta 서버의 지연이나 지속 운영 수용량 보장이 아니다.

### 실제 시계 + 공개 답글 경쟁

[묶음 실행 JSON](m1-3-realtime-batch.json). private reply 3,000건 + 공개 답글 3,000건을 동시에 넣었다. 계정당 private 400/h, public 120/h; 각 HTTP 응답에 1초 지연을 넣었다. 운영 프로세스와의 자원 경쟁을 줄이기 위해 전용 PG 컨테이너를 **0.75 CPU/1GiB**, 시험 프로세스를 nice 15로 제한했다.

- 6,000건 수락, 누락/중복/unknown 0. 최대 HTTP 동시 호출 64.
- 전체 380.048초, private reply 완료 161.623초.
- 단순 DM ETA 108초 대비 +53.623초. 이 실행기는 한 batch가 모두 끝난 뒤 다음 batch를 시작하므로 긴 응답이 같은 묶음의 다음 작업도 지연시킨다.
- 250계정 각각 12건인 실제 시험만으로 400/h 경계를 입증하지 않는다. 그 경계는 위 401건 가상 시계 통합 시험과 토큰/rolling guard 단위 시험으로 확인했다.

### 기존 worker loop를 재사용한 연속 실행

[연속 실행 JSON](m1-3-realtime-continuous.json). 같은 250계정/6,000작업, 1초 HTTP 지연, PG 0.75 CPU/1GiB에서 기존 `startEventLoop`를 concurrency 64/poll 250ms로 실행했다. 슬롯이 비면 다음 due 작업을 즉시 가져온다.

| 항목 | 결과 |
| --- | ---: |
| DM / 공개 답글 수락 | 3,000 / 3,000 |
| 누락 / 중복 / unknown | 0 / 0 / 0 |
| 전체 완료 | 358.696초 |
| DM 완료 | 130.464초 |
| 단순 DM ETA / 실제 오차 | 108초 / +22.464초 |
| 최고 HTTP 동시 요청 | 64 |

DM ETA 오차는 사전에 제안한 `max(60초, ETA의 5%)` 이내다. 이 결과는 **250계정의 이 대기열 버스트**를 검증하며 모든 계정의 지속 최대 발송·실제 Meta 지연·다른 서비스의 최대 CPU 부하까지 보장하지 않는다. 운영 대시보드 ETA에는 공통 queue/실측 지연 보정이 필요하다. 한 시간 이상 실제 시계 soak, 실제 Meta 두 계정 테스트, metadata/legacy/대시보드까지 합친 혼합 부하는 배포 전 추가 검증 대상이다.

재현 (반드시 폐기 가능한 TEST_DATABASE_URL 지정):

```sh
GONGGU_DISPATCH_LOAD_REPORT=/tmp/virtual.json pnpm test tests/integration/campaign-dispatch-load.test.ts
GONGGU_DISPATCH_REALTIME=1 GONGGU_DISPATCH_CONTINUOUS=1 GONGGU_DISPATCH_PUBLIC=1 GONGGU_DISPATCH_HTTP_DELAY_MS=1000 GONGGU_DISPATCH_LOAD_REPORT=/tmp/realtime.json pnpm test tests/integration/campaign-dispatch-load.test.ts -t 'sends 3,000'
```

## 화면 → 서버 → DB → 새로고침

[일시정지 화면](m1-3-paused.png). 390px 모바일 크기, 전용 browser DB, localhost 미리보기, 외부 요청 차단 fixture로 검증했다.

1. 공구 상세에서 전체 정지와 계정 cap 450/h를 저장했다. Server Action POST 200.
2. 새로고침 뒤 checkbox와 450 값이 유지됐다. 브라우저 JS 오류 0, 가로 overflow 없음.
3. 정지를 해제하고 다시 저장했다. DB `manual_paused=false, private_reply_rate=450, version=3`; 감사 로그에 정지/재개 두 행이 남았다.
4. 미리보기를 종료했다. 마지막 화면 refresh 도중 브라우저 종료에 따른 stream-close 로그가 있었으며 실제 작업 응답/DB 저장은 완료됐다.

화면은 집계와 보호 상태만 표시하며 토큰·댓글 작성자 식별정보를 전달하지 않는다. 실제 Instagram 화면/발송 스크린샷은 아직 없으며 모의 화면으로 대체했다고 주장하지 않는다.

`pnpm typecheck`, `pnpm lint`, `pnpm build:worker`, Next 프로덕션 빌드, `git diff --check`를 확인했다. 타입 검사와 Next 빌드는 `.next/types`를 공유하므로 순차 실행한다. 초기 병렬 실행의 생성 파일 경합은 순차 재실행으로 해소했다.

부하 시험 후 운영 web/worker/PostgreSQL 컨테이너는 모두 running이며 재시작 수 0, web/DB health는 healthy였다. 운영 배포나 마이그레이션은 실행하지 않았다. 이 관찰만으로 전체 운영 트래픽의 성능 영향을 입증했다고 주장하지 않는다.
