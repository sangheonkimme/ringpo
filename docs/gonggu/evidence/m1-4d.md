# M1-4d — 실제 워커 연결과 기존 팔로우 DM 공통 예산

검증일: 2026-10-21. 운영 배포·DB 변경·실제 Meta 발송은 하지 않았다.

## 변경과 검증 범위

서명된 메시지는 영속 inbox에 저장한 뒤 응답한다. 공구 router/sender/inbox와 기존 댓글 worker를 연결하고, 기존 팔로우 후속 DM도 공통 계정 예산·발송 원장·24시간 창을 거친다. API 응답 유실/5xx/worker 유실은 확인 필요로 남긴다. 기존 OFF 경로, flag 전환 중 이관, 미완료 guarded gate에 대한 OFF 후 응답을 구분한다.

기존 기록의 checks만으로 발송 여부를 알 수 없으면 `legacy_follow_history_unverified`로 표시한다. waiting 상태를 근거로 과거 링크를 자동 재전송하지 않는다. API 호출 전 이관된 현재 요청은 구 checks 증가분을 되돌린다. 신규 guarded 발송은 구 checks 대신 intent 원장을 사용한다.

## 자동·화면 검증

- 팔로우 발송/이관 2개 파일 19개 테스트 통과(11.38초).
- 실제 worker loop, 서명된 webhook, 기존 OFF 회귀, 메시지 수신·팔로우, 마이그레이션을 포함한 6개 파일 47개 테스트 통과(42.57초).
- 타입 검사, lint, Next 프로덕션 빌드, worker 빌드 통과.
- 로컬 프로덕션 빌드에서 인증된 공구/기존 자동화 화면을 390×844 모바일 브라우저로 확인했다. HTTP 200, JS 오류 0, 가로 넘침 없음. 대기·실패·확인 필요 각각 1건의 fixture를 확인했다. [공구 화면](m1-4d-campaign-inbox.png), [기존 자동화 화면](m1-4d-legacy-inbox.png).
- `0008` empty up/down/up 통과. unknown/source/untracked marker가 존재하면 down을 거부한다. 기존 `0007` 시험도 고정된 이전 스키마에서 수행한다.
- 전체 회귀 첫 실행은 종료 코드 143으로 요약 없이 중단되어 통과로 계산하지 않았다. 진행 로그를 남기는 전체 재검사와 250계정 실시간 혼합 부하 결과는 실행 완료 후 이 문서에 기록한다.

부하 시나리오는 `campaign-runtime-load.test.ts`의 opt-in 시험이다. 일반 테스트에서는 건너뛰며 `GONGGU_RUNTIME_LOAD=1`로 실행한다. 전용 PostgreSQL에서 캠페인 댓글 3,000개를 실제 10분에 걸쳐 3회씩 전달하고 기존 팔로우 흐름 250개, 대시보드 250개/30초 상당 조회를 함께 실행한다. 로컬 HTTP의 읽기 100ms/쓰기 1초 지연, router 32/sender 64/inbox 8/legacy 8, PG pool 10을 사용한다. 외부 Meta 요청은 0건이다. **아직 실행 결과로 수용량을 주장하지 않는다.**

## 배포 조건

추가 OAuth scope는 없다. [설계 §2의 공식 Meta 문서](../01-design.md)를 2026-10-21 확인한 범위에서 기존 basic/manage_comments/manage_messages를 사용한다. 실제 두 테스트 계정으로 sender IGSID·동의·팔로우·private reply 형식·echo capability를 확인해야 한다. postback만으로 동의/창을 추정하지 않으며 기본은 직접 답장 요청이다.

모든 구 웹/워커를 drain하고 호환 버전으로 교체해야 한다. 신규 코드와 구 untracked sender의 동시 실행은 지원하지 않는다. 플래그 기본값은 OFF이며 이번 PR에서 운영에 켜지 않는다. pending 처리/원장은 PostgreSQL에 있고 Redis는 추가하지 않는다.
