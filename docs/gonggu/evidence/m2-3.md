# M2-3 — 공구 FAQ·직접 답변 인계

검증일: 2026-10-22 UTC. 운영 배포/마이그레이션/실제 Meta 발송 없음. PostgreSQL 17 분리 DB와 모의 Graph만 사용했다.

## 확인 내용

- 기존 signed inbox/DM queue를 재사용. 실제 사용자 문의의 24시간 창, 한 문의당 답변 하나, 우선순위·제외어·정확 일치·최신 답변, source 삭제·기한, 공구 문맥 모호성, entitlement/소유권, 계정별 FAQ 검증 gate를 검사한다.
- 셀러 echo가 들어온 즉시 대화에 보류 표식을 둔다. 링포 HTTP 결과보다 echo가 빠른 경우, 여러 echo/중복/worker 재시작, 직접 답한 문의의 재발송 차단, 수동 재개 후 새 문의만 허용, unknown 확인 필요를 검증한다.
- 최초 scoped 시험은 잘못된 문자열 게시물 ID fixture 1건을 수정했다. 이후 단위/통합/마이그레이션/기존 inbox·공구 팔로우 5개 파일/42개 테스트 통과(57.47초). 추가로 source 창 만료·unknown·대화 pagination 시험을 넣어 전체 회귀에 포함했다.
- 타입 8.46초, lint 11.47초, production Next build 40.03초, worker build 0.74초 통과.
- 모바일 390×844 standalone에서 [FAQ 작성·수정](m2-3-faq.png), [대화 일시정지·새 문의 재개](m2-3-handoff.png) 확인. 직접 답변 검증 전 자동 발송 차단 안내가 보인다. 키워드·답변 생성/수정 후 새로고침해 값 유지, 모의 받은 문의/셀러 echo 이후 자동 pause 표시, 수동 재개/정지 성공. HTTP 200, JS 오류 0, 가로 넘침 없음. 화면은 직접 시각 확인했다. 긴 전체 화면에는 기존 고정 header/footer가 함께 촬영된다.
- 브라우저 편집 시험의 초기 Playwright `getByLabel` 선택자를 실제 접근성 트리의 textbox 역할로 바꿔 재검증했다. UI의 편집/저장은 정상이며 입력값이 있는 textarea도 같은 접근성 이름으로 조회한다.
