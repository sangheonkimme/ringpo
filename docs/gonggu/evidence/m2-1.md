# M2-1 — 오픈 발송 예상과 만료 위험

검증일: 2026-10-21. 운영 배포·실제 Meta 발송 없음. 새 마이그레이션 없음.

## 구현

현재 계정/캠페인의 토큰·rolling-hour 사용량, 대기열 EDF 순서, 지터·재시도·cooldown·마감·7일 만료를 반영한 예상이다. 단순 `대기 수 ÷ 속도`와 구분한다. 수동 정지·정책 검토 중에는 완료 시각을 약속하지 않고 알려진 최소 위험 수를 표시한다. 미리보기는 저장 전 DB를 변경하지 않는다. 표시 분이 같은 수동 OPEN 시각의 초/밀리초도 편집 시 보존한다.

## 검증

- 단위 13개 통과(순수 계산 시험 0.699초): EDF, 401건 rolling-hour 경계, 3,000건 다시간 예측, fallback 남은 창, 마감, 재시도·정지, 750/h 지터, UTC/KST 편집.
- 통합 2개 파일/8개 통과(7.99초): Meta 작성 시각 기준 위험, 일정·fallback 미리보기의 무변경성, 소유권/flag, 기존 발송 설정 조회.
- 타입 검사, lint, Next 프로덕션 빌드 통과.
- 인증된 모바일 390×844 프로덕션 빌드에서 [위험 표시](m2-1-risk.png)와 [대체 안내 미리보기](m2-1-fallback-preview.png) 확인. JS 오류 0, 가로 넘침 없음. 익명 endpoint 401, 잘못된 일정 400, `private, no-store` 확인. 모든 외부 요청은 차단한 fixture다.

## 예측 한계

새 댓글·미처리 metadata·기존 자동화 처리 순서·전역 worker 경쟁은 결과를 늦출 수 있으며 화면에 밝힌다. 관측된 해당 계정 HTTP p95를 사용하고 이력이 없으면 1초 가정이라고 표시한다. 대기열이 10,000개를 넘으면 예측 시뮬레이션만 중단하고 전체 위험 수는 별도로 집계한다.

[M1 실제 250계정 혼합 부하](m1-4d-mixed-realtime.json)는 오픈 후 3,000건 완료 128.637초, 단순 108초 대비 +20.637초였다. 이는 M2 화면 추가 전 runtime의 측정이며 새 예측 화면의 성능 측정으로 바꾸어 표기하지 않는다. 후속 M2 전체 흐름에서 조회 부하를 다시 확인한다.
