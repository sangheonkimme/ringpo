# M1-4a 추적 링크·상품 선택·메시지 렌더링 검증

확인일: 2026-10-21 UTC. 이 PR은 M1-4를 작은 단위로 나눈 첫 부분이다. 외부 Meta 송신과 운영 배포는 실행하지 않았다. 공통 legacy 예산과 동의 기반 팔로우 수신은 다음 PR에서 연결한다.

## 자동 검증

전체 **53개 파일/347개 테스트**를 통과했다(275.44초). 기존 자동화와 부하 시험을 포함한다. 관련 6개 파일/32개 테스트도 별도로 통과했다. 이후 대시보드 조회를 같은 transaction에서 갱신되는 링크별 counter 합계로 변경해 클릭 원문 전체를 반복 스캔하지 않게 했고, 추적 통합 7개 테스트를 다시 통과했다.

타입 검사, lint, worker 빌드, Next 프로덕션 빌드와 diff 공백 검사를 통과했다. 빌드 환경은 가짜 OAuth/이메일 설정과 별도 browser DB이며 외부 요청 차단 fixture를 사용했다. 회귀 검사 중 운영 strict health는 HTTP 200(`db=true, worker=true`), web/worker/DB 모두 running, 재시작 0이었다. 운영 마이그레이션과 배포는 하지 않았다.

- 같은 잡에 대한 8개 동시 렌더 요청이 상품별 코드 하나로 수렴한다. URL/상품 수정은 새 링크를 만들고 이미 전달된 URL/catalog는 바뀌지 않는다.
- 25개 동시 클릭 요청의 이벤트 수와 캐시 counter 합계가 일치한다. 같은 수신자의 다른 상품 클릭은 고유 1명으로 집계하고 다른 수신자가 클릭하면 고유 수가 증가한다.
- Facebook/Meta crawler, HEAD, preview/prefetch는 HTTP 302지만 클릭은 0이다. 실제 사람 GET만 반영한다. 임의 query로 redirect 목적지를 바꿀 수 없다.
- 로그인 없는 상품 선택 DTO에는 제목·브랜드·상품명·옵션·code만 있다. 원본 IGSID, 수신자 HMAC, 소유자 ID, 잡 ID를 노출하지 않는다. 클릭 이벤트에 IP/UA/원본 수신자 ID가 없다.
- 계정 삭제 시 추적 링크/catalog/해시 클릭이 함께 삭제된다. 운영 잡 보존 기간 정리로 job이 삭제될 때 이미 발송한 링크는 유지된다.
- 실제 dispatcher → renderer → fixture Meta 수락 → catalog → HTTP redirect → 클릭 집계를 연결했다. 같은 lease 재실행은 외부 발송을 반복하지 않는다.
- 긴 한글/이모지/반복 placeholder도 UTF-8 1000byte 한도에서 구매 링크를 온전히 보존한다. 공개 답글 순환·단계별 템플릿·팔로우 응답 유도·만료 일정과 게시물 링크를 검증한다.
- `0005` up/down/up 및 발송된 catalog가 있을 때 파괴적 down 거부를 전용 DB에서 확인했다. 생성된 SQL의 참조 순서를 수정해 복합 FK 대상 UNIQUE를 먼저 만든다.

이 검증의 동시 요청 수는 전체 250계정 서비스 부하와 구분한다. 발송 엔진의 250계정/6,000작업 측정은 [M1-3 결과](m1-3.md)에 있으며, 추적 링크 렌더링까지 포함한 혼합 부하는 M1-4 연결 단계에서 다시 측정한다.

## 브라우저 전체 흐름

전용 browser PostgreSQL, localhost:3107, 390px 모바일 viewport. Meta GET은 fixture, 외부 write는 차단했다. 상품 도착 페이지도 로컬 응답으로 대체했다.

1. **로그아웃** 상태에서 상품 선택 화면 HTTP 200, 상품/옵션 2개 표시. HTML에 수신자·잡·소유자 식별정보가 없고 `noindex`를 확인했다. [상품 선택 화면](m1-4a-catalog.png)
2. Meta preview와 HEAD를 보낸 뒤 셀러 화면이 고유 0명/전체 0회임을 확인했다.
3. 브라우저 상품 클릭과 별도 상품 GET 각각 HTTP 302. DB commit 후 셀러의 자동 새로고침으로 **30.325초** 안에 고유 1명/전체 2회가 표시됐다. [집계 화면](m1-4a-clicks.png)
4. 브라우저 JS 오류 0, 가로 overflow 없음. 공개 링크는 no-store/no-referrer이며 상품 anchor는 prefetch하지 않는다.

화면에 있는 개인별 단축 코드는 테스트용 가짜 데이터다. 실제 Instagram 메시지/버튼 검증 스크린샷은 별도 계정 지정 후 진행하며 이 화면으로 대신했다고 표시하지 않는다.

## 운영과 롤백

기능 플래그 OFF에서도 이미 보낸 링크는 계속 열린다. `0005` down은 추적 데이터가 없을 때만 허용하며 운영에서는 flag OFF와 호환 버전으로 롤백한다. 기존 `/l/{code}`의 테이블·resolver·동작은 변경하지 않았다. 신규 OAuth 권한은 없다.
