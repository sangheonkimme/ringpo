## 백업과 사전 확인

운영 DB와 배포 환경 파일을 저장소 밖의 운영자 전용 경로에 권한 0600으로 백업했다. DB custom archive 목록을 읽고 외부 네트워크·호스트 공개 포트가 없는 PostgreSQL 17 임시 컨테이너에 복원했다. 복원본에 새 이미지의 migrator를 실행하고, 재실행도 정상 종료함을 확인했다. 운영 전환 직전 웹·워커를 중지한 상태에서 DB를 한 번 더 백업했다.

복원본과 운영 DB 모두 기존 사용자 2개, 연결 계정 1개, 자동화 1개, 댓글 이벤트 1개의 레코드 수가 유지됐다. 운영의 공구·DM 잡·발송 시도·메시지 수신함은 모두 0건이다. 백업 파일에 실제 데이터가 있으므로 저장소나 공개 산출물에 첨부하지 않는다.

새 이미지 빌드에서 Next 빌드·TypeScript 검사·worker bundle이 통과했다. 복원본에서만 생성한 임시 로그인 세션과 가짜 앱 비밀값으로 다음 응답을 확인했다. 실제 운영 사용자의 로그인 세션은 생성하거나 사용하지 않았다.

| 확인 | 결과 |
| --- | --- |
| 기존 대시보드·자동화 목록 | 로그인 상태 HTTP 200 |
| 플래그 OFF의 공구 목록 | HTTP 404 |
| 복원본에서 계정 하나만 ON | 공구 목록·새 공구 폼 HTTP 200, 제목 확인 |
| 로그인된 사용자의 `/login` | 정상 리다이렉트 HTTP 307 |
| 비로그인 공구 목록 | `/login`으로 HTTP 307 |
| PDF 한글 폰트 패키징 | 런타임 이미지 안에 폰트 존재 |

최초 smoke 스크립트가 로그인된 `/login`에 200을 기대해 실패했다. 실제 동작인 307을 기대하도록 스크립트를 바로잡은 뒤 위 검사들이 통과했다. 제품 코드는 변경하지 않았다. 이 확인은 서버 렌더 응답이며 새로운 브라우저 상호작용 시험은 아니다. 기존 화면·부하 검증은 [M2-5](m2-5.md)에 있다.

## 운영 전환과 외부 확인

기존 웹을 중지한 뒤 워커를 정상 종료하고, 최종 백업 → 마이그레이션 → 새 웹·워커 시작 순서로 처리했다. PostgreSQL·백업 컨테이너는 재시작하지 않았다. 중지 시작부터 외부 strict health 정상 응답까지 **9.473초**였다. 새 컨테이너 시작 시각은 00:24:52 UTC이며 새로운 worker ID의 heartbeat 갱신을 확인했다. 초기 확인에서 두 컨테이너의 재시작 횟수는 0, 웹 Docker health는 healthy, 시작 로그에는 오류가 없었다.

| 운영 확인 | 결과 |
| --- | --- |
| `/api/health?strict=1` | HTTP 200, `ok/db/worker=true` |
| 홈페이지·로그인 | HTTP 200 |
| 비로그인 `/app/campaigns` | 로그인으로 HTTP 307 |
| 비로그인 예상 발송 API | HTTP 401 |
| 존재하지 않는 공유 토큰·추적 링크 | HTTP 404 |
| Meta webhook GET 검증 | challenge 정상 반환 |
| 유효한 서명의 빈 webhook | HTTP 200, `ok`, 생성 이벤트·잡 0 |
| 서명 없는 빈 webhook | HTTP 401 |

웹훅 확인은 `entry: []`인 요청만 사용했다. 실제 댓글·수신자를 만들거나 Meta 메시지를 보내지 않았다. 검증 토큰·서명 비밀값은 출력하지 않았다.

## 되돌리기와 다음 공개

직전 이미지와 백업을 보관한다. 배포 스크립트는 마이그레이션·strict health 실패 시 이전 이미지로 웹·워커를 복구하도록 준비했으며 이번에는 실행되지 않았다. 운영 데이터가 있는 스키마를 DROP하지 않는다. 현재는 두 기능 플래그가 OFF이고 신규 공구 데이터가 없어, 화면 공개 전에 이전 이미지로 돌아갈 수 있다. 이후 계정 활성화·공구 데이터 생성 후에는 런북의 호환 코드 및 기능 플래그 롤백 절차를 따른다.

현재 운영은 기능 브랜치의 특정 이미지에 고정되어 있다. 다음 main 자동 배포 전에 공구 변경의 병합 여부를 확인해야 한다. 계정 공개 범위가 정해지면 그 범위만 활성화하고, FAQ는 실제 셀러 직접 답변 감지를 확인한 계정에만 별도로 연다.
